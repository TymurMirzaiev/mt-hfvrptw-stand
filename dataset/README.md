# Набір тестових задач MT-HFVRPTW (тези МПЗІС-2026)

Задачі, на яких проведено абляційне дослідження в тезах
Мірзаєв Т. Р., Михальчук Г. Й. «Escaping local optima in multi-objective iterated local search for heterogeneous fleet vehicle routing: an ablation study», МПЗІС-2026.

## Що всередині

| Папка | Файлів | Що це |
|---|---|---|
| `generated/` | 18 задач (`.txt` + `.json`) | власний генератор: класи R (випадково), C (купками), RC (змішано) × 25, 50, 100 клієнтів × 2 задачі; фіксовані зерна |
| `solomon_derived/` | 18 задач (`.txt` + `.json`) | похідні від задач Соломона R101, R201, C101, C201, RC101, RC201 (перші 25, 50, 100 клієнтів) з доданими трьома типами ТЗ, об’ємом і зоною |
| `solomon_original/` | 56 задач (`.vrp`) + 56 найкращих відомих розв’язків (`.sol`) | класичний набір Соломона на 100 клієнтів у форматі VRPLIB з колекції PyVRP (ліцензія MIT, файл `LICENSE_PyVRP_Instances.txt`); використано для перевірки стенда (середній розрив 1,11 %) |

Назва файлу: `R25_0` — клас R, 25 клієнтів, задача 0; `C101_50` — похідна від C101, перші 50 клієнтів.

## Формат `.txt`

Заголовок `КЛЮЧ : значення`, далі дві секції:

```
VEHICLE_TYPES_SECTION
# id name mass_cap volume_cap fixed_cost cost_per_dist speed emission_per_dist service_mult
1 truck 220 48 190 1.45 0.85 1 1.4
NODE_SECTION
# id x y mass volume ready due service   (вузол 0 — склад)
0 50 50 0 0 0 720 0
...
EOF
```

У `.txt` числа округлено до 4 знаків; у `.json` — повна точність (саме ці значення використовував стенд).

## Правила моделі

- **Парк:** три типи (вантажівка, фургон, вантажний велосипед), кількість машин кожного типу не обмежена.
- **Відстані:** евклідові без округлення. Фургон — звичайна відстань. Вантажівка — ×`TRUCK_ZONE_FACTOR` (1,55) на дугах, середина яких лежить у колі `ZONE_CENTER`, `ZONE_RADIUS`. Велосипед — ×`BIKE_FACTOR` (0,88) на всіх дугах.
- **Час руху** = відстань / швидкість типу. **Час обслуговування** = `service` вузла × `service_mult` типу.
- **Обмеження:** маса й об’єм кожного рейсу не перевищують місткості типу; прибуття не пізніше `due` (раніше — чекати до `ready`); кожен клієнт обслуговується рівно один раз; машина може зробити кілька рейсів, між ними — `RELOAD_TIME` на складі; усе закінчується до `HORIZON`.
- **Критерії (мінімізуються):** вартість = Σ(постійні витрати + вартість за одиницю × пробіг) за використаними машинами; викиди = Σ(викиди на одиницю × пробіг); час завершення = момент закінчення роботи останньої машини.
